# The Truth Filtering Engine

지도에서 음식점·카페를 탐색할 때 광고성 가능성이 높은 리뷰를 분류해, 사용자가 신뢰할 수 있는 리뷰를 먼저 확인하도록 돕는 지도 기반 광고성 리뷰 필터링 NLP 서비스입니다.

## 문제 정의

사용자는 보통 네이버 지도나 카카오맵에서 음식점 핀을 누른 뒤 리뷰를 확인합니다. 하지만 블로그 리뷰에는 협찬, 광고성 표현, 과도하게 정제된 문구가 섞여 있어 실제 방문 판단에 시간이 많이 듭니다.

맛집 하나를 고르기까지 검색, 블로그 리뷰 탐색, 광고 여부 판단, 재검색이 반복되면서 평균 15~20분이 소모되는 흐름을 문제로 정의했습니다.

리서치에서는 소비자 61.7%가 리뷰를 보고 실패한 경험이 있다고 답했고, 리뷰가 너무 많은 제품은 오히려 의심된다는 응답도 35.2%였습니다. 또한 2024년 SNS 모니터링에서 뒷광고 의심 게시물이 22,011건 발견되었고, 이 중 네이버 블로그가 9,423건으로 큰 비중을 차지했습니다.

이 프로젝트는 사용자가 지도 기반 탐색 흐름을 유지하면서, 리뷰의 광고성 가능성을 함께 확인할 수 있도록 구성했습니다.

## 핵심 기능

| 기능 | 설명 |
| --- | --- |
| 지도 기반 장소 탐색 | Kakao Map 기반으로 음식점·카페를 탐색하고 선택합니다. |
| 리뷰 수집 및 캐싱 | Naver Blog API로 리뷰를 가져오고 Supabase에 저장해 재사용합니다. |
| 광고성 점수 표시 | 리뷰 제목과 본문을 전처리한 뒤 ELECTRA 기반 분류 모델로 광고 가능성을 계산합니다. |
| 상세 리뷰 분석 | 장소 상세 화면에서 리뷰 목록, 광고성 판단 결과, 원문 링크를 확인합니다. |
| 북마크·최근 기록 | 사용자가 관심 장소와 최근 분석 이력을 다시 확인할 수 있게 합니다. |
| 위치 기반 추천 | 현재 위치 주변 음식점 중 광고 가능성이 낮은 리뷰를 우선적으로 확인할 수 있게 합니다. |
| 사용량 관리 | 무료 분석 횟수, 프리미엄 횟수, 코인 차감 흐름을 백엔드에서 관리합니다. |
| 앱·웹 제공 | 초기 Flutter 앱에 더해 React 웹 화면을 추가했습니다. |

## 시스템 아키텍처

```text
Flutter App / React Web
        |
        v
FastAPI Backend
        |
        +-- Kakao Map / Kakao Local API: 지도 표시, 장소 검색, 위치 기반 탐색
        +-- Naver Blog API: 장소 관련 블로그 리뷰 수집
        +-- Supabase: 리뷰, 사용자 상태, 북마크, 최근 기록 저장
        +-- ELECTRA 기반 분류 모델: 리뷰 광고성 가능성 추론
```

## AI/NLP 모델 활용 방식

이 프로젝트의 AI 활용 범위는 리뷰 텍스트 분류입니다.

1. 장소명, 리뷰 제목, 리뷰 본문을 수집합니다.
2. HTML 태그와 불필요한 표현을 정리합니다.
3. 가게명이 모델 판단에 과하게 영향을 주지 않도록 가게명을 일반 표현으로 마스킹합니다.
4. 제목과 본문을 결합해 ELECTRA 기반 분류 모델에 입력합니다.
5. 모델이 반환한 광고 가능성 점수를 기준으로 진성 리뷰, 의심 리뷰, 광고성 리뷰에 가깝게 구분합니다.

모델 개선은 다음 방향으로 진행되었습니다.

| 항목 | 내용 |
| --- | --- |
| 일반화 문제 확인 | 기존 검증 데이터에서는 AUC 약 0.95, F1 0.9693 수준이었지만 신규 테스트 데이터에서는 AUC 0.58까지 하락했습니다. |
| 데이터 편중 완화 | 가게 수를 34개에서 122개로 늘리고, 데이터 수를 1,360개에서 2,142개로 확대했습니다. |
| 가게명 노이즈 제거 | 음식점 브랜드명과 지점명을 일반 표현으로 치환해 새로운 가게에 대한 일반화 성능을 개선했습니다. |
| 입력 방식 개선 | 리뷰 제목과 본문 preview를 `제목 [SEP] 본문` 형태로 결합했습니다. |
| 최종 실험 결과 | 최종 모델 실험에서 PyTorch FP32 AUC 0.8397, F1 0.7788을 기록했습니다. |

현재 레포만으로 학습 데이터와 실험 전체를 재현할 수 있는 상태는 아닙니다. 따라서 이 프로젝트는 모델 연구 성과만을 강조하기보다, NLP 모델을 실제 서비스 흐름과 API에 연결한 경험으로 설명하는 것이 적절합니다.

## 백엔드

백엔드는 FastAPI로 구성했습니다.

| 영역 | 설명 |
| --- | --- |
| 장소 검색 | Kakao Local API를 활용해 현재 위치나 지도 중심 기준의 음식점·카페 정보를 조회합니다. |
| 리뷰 수집 | Naver Blog API를 호출해 장소 관련 블로그 리뷰 후보를 수집합니다. |
| 리뷰 저장 | Supabase에 리뷰, 장소 정보, 분석 결과를 저장하고 캐시처럼 재사용합니다. |
| 모델 추론 | 전처리된 리뷰 텍스트를 ELECTRA 기반 분류 모델에 전달해 광고 가능성 점수를 계산합니다. |
| 사용자 기능 | 북마크, 최근 기록, 사용량 관련 상태를 API로 제공합니다. |
| 지역 필터 | Kakao 좌표-행정구역 변환 결과를 여러 축약형으로 처리해 위치 기반 추천의 누락을 줄였습니다. |
| 사용량 차감 | 동일 매장 반복 분석 예외, 무료 횟수, 프리미엄 횟수, 코인 차감 우선순위를 백엔드에서 처리합니다. |

초기 배포는 로컬 FastAPI 서버를 Cloudflare Quick Tunnel로 외부 노출하고, 웹 클라이언트는 Vercel을 활용하는 방식으로 구성했습니다. 다만 Cloudflare Quick Tunnel의 버퍼링 때문에 SSE 스트리밍이 안정적으로 동작하지 않는 한계가 확인되었습니다.

## 데이터 흐름

```text
1. 사용자가 지도에서 음식점·카페를 검색하거나 선택
2. 프론트엔드가 FastAPI 백엔드에 장소·리뷰 요청
3. 백엔드가 Kakao API로 장소 정보를 보강
4. 백엔드가 Naver Blog API로 리뷰 후보 수집
5. 리뷰 제목·본문 전처리 및 가게명 마스킹
6. ELECTRA 기반 모델로 광고 가능성 점수 계산
7. Supabase에 리뷰와 분석 결과 저장
8. 앱·웹 화면에서 리뷰 목록, 점수, 원문 링크 표시
```
